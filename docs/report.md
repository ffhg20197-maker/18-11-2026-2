# Отчёт по практической работе — тема 3.2.50

## Цель
Изучить конфигурационные файлы WordPress и подготовить защитную конфигурацию Apache/PHP/CMS.

## Базовый уровень (30 баллов)
### 1.1 — .htaccess (10)
Создан файл с отключением листинга каталогов, защитой wp-config.php директивой Require all denied и стандартной маршрутизацией WordPress. RewriteCond исключают существующие файлы и каталоги из перенаправления на index.php.

### 1.2 — защита wp-config.php (10)
Apache 2.4 блокирует прямой HTTP-доступ к конфигурационному файлу. В динамической среде необходимо проверить запрос /wp-config.php и убедиться, что PHP-код не раскрывается; ожидаемый ответ обычно 403, возможна обработка как 404 в зависимости от окружения.

### 1.3 — robots.txt (10)
Добавлены User-agent: *, Disallow: /wp-admin/ и Allow: /wp-admin/admin-ajax.php. Sitemap содержит демонстрационный URL, который нужно заменить на фактический адрес сайта. robots.txt не является механизмом авторизации.

## Средний уровень (35 баллов)
### 2.1 — безопасная отладка (15)
В WORDPRESS_CONFIG_EXTRA заданы WP_DEBUG=true, WP_DEBUG_LOG=true, WP_DEBUG_DISPLAY=false и display_errors=0. Это направляет диагностику в wp-content/debug.log и не выводит ошибки посетителям. Реальное появление записи проверяется после запуска WordPress.

### 2.2 — отключение редакторов (10)
DISALLOW_FILE_EDIT=true отключает встроенные редакторы тем и плагинов в панели администратора. Это снижает последствия компрометации админской учётной записи, но не заменяет обновления, MFA и файловые ограничения.

### 2.3 — HTTPS (10)
Подготовлен deploy/https-redirect.conf.example. %{HTTPS} показывает состояние TLS на Apache, %{HTTP_HOST} содержит имя хоста. 301 — постоянный редирект, 302 — временный. Локальный стенд остаётся на HTTP до настройки TLS, чтобы избежать цикла/недоступности.

## Продвинутый уровень (25 баллов)
### 3.1 — ротация ключей и солей (15)
WordPress использует восемь ключей и солей для cookies и nonce. Замена полного набора аннулирует действующие cookie, поэтому пользователям потребуется повторная авторизация. Генерацию выполняют официальным генератором WordPress Salts; реальные значения нельзя хранить в Git. Саму ротацию и выход из сессии требуется показать на запущенном экземпляре.

### 3.2 — права доступа (10)
deploy/permissions.sh назначает 400 для wp-config.php и 644 для .htaccess/robots.txt. PHP читает wp-config.php при условии, что процесс имеет доступ как владелец файла. Перед применением проверяются владелец и пользователь процесса, иначе сайт может перестать работать.

## Проверка
Запуск статических проверок: python3 tests/check-config.py. В подготовленном рабочем окружении все 9/9 статических проверок пройдены. Динамические проверки браузера, панели WordPress, реального debug.log, ротации сессий и chmod требуют запуска Docker/WordPress на целевой машине.
